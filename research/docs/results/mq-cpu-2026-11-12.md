# MosaicQwen：CPU で確かめた結果（2026-11-12）

計画：docs/plan-mosaic-qwen.md。生データ（ログ・数値・学習した重み）：このリポジトリに移す前の Eureka-COM/memory-mosaics-LLM の `results/2026-11-11_1758_mq-cpu` ブランチ（日時は UTC）。
実行環境：CPU 2 コア・メモリ 6GB 強の作業環境。GPU は使っていない。

**分かったこと**：変換・3 段の学習・評価・書き出しは、本物の Qwen3.5-0.8B で最後まで動く。学習の向きも正しい（誤差も KL も下がる）。
ただし CPU で回せた量（約 17 万トークン）は GPU の計画（2,400 万トークン）の 0.7% で、**品質はまだ出ていない**。
とくに、文脈の中の数字を写して答える力（想起）は 0% のまま。ここが GPU の最初の実行（D1）で確かめる中心になる。

## 1. 試験

| 範囲 | 結果 |
|---|---|
| 新しい試験 21 件（`test_official_vendor.py`・`test_mosaic_qwen.py`・`test_mq_scripts.py`） | すべて合格 |
| 元のリポジトリの既存の試験と合わせた全体 | 75 件合格（元のリポジトリで実行。こちらには本線の試験だけを移した） |

新しい試験が確かめていること：
- 同梱した公式コード 49 ファイルが、記録したハッシュと一致する。1 ファイルを書き換えると検出して止まる
- CPU 用の密な注意計算が、PyTorch の FlexAttention と一致する（差 1e-5 未満。読めるものが無い行は 0）
- 漏れ平均の並列計算が、公式の参照実装と一致する（値は 1e-10 未満、勾配は 1e-9 未満。途中のリセットと初期状態つき）
- 変換後、注意の層はすべて公式の `MosaicBlock`（中の記憶は公式の `MosaicsMemory`）。生徒に注意のパラメータもモジュールも無い
- 教師として動かすと、変換前のモデルと出力が完全に一致する（差 0）
- 新しい記憶を黙らせると、変換した層は「元の層から注意を除いたもの」と一致する（持続の記憶と正規化は元の重み）
- 未来のトークンを変えても、それより前の出力は変わらない
- キャッシュを使った生成（まとめて読ませる・1 トークンずつ・途中で数トークンまとめて）が、全体を 1 回で計算した結果と一致する。2 つの生成を交互に進めても混ざらない。`generate` も動く
- `--replace all`（64 層すべてを置き換える切り替え）でも同じ試験が通る
- 段 1 → 再開 → 段 2（記憶＋LoRA／勾配チェックポイント／全重み＋別の教師）→ 評価 → 書き出し → 読み直しが通る。書き出したファイルに注意の重みが無い

## 2. 27B の実寸の層での確認（`scripts/mq_port27.py`）

Qwen3.8-27B の設定ファイルどおりの形（幅 5,120、MLP 17,408、24 ヘッド×256）の注意層を、乱数の重みで 1 層作って変換した。

| 項目 | 結果 |
|---|---|
| 教師＝変換前のモデル | 差 0 |
| キャッシュ生成＝全体計算 | 最大差 1.1e-5 |
| 生徒に残る注意のパラメータ | 0 |
| 1 層で増える記憶（16+16 ヘッド×128） | 63,406,240 |
| 1 層で消える注意 | 104,858,112 |
| 27B 全体（注意 16 層） | 記憶 +10.14 億、注意 −16.78 億。277.8 億 → 271.2 億パラメータ |
| 記憶の大きさ | fp32 で 3.78GB、bf16 で 1.89GB。最適化の状態（Adam）は 7.56GB |
| 生成時に 1 トークンあたり持つ数 | long 4,096（元の注意は 2,048） |

Gated DeltaNet の層を含む組み合わせ（`--pattern LA`）は、この環境のメモリでは回していない。

## 3. 本物の Qwen3.5-0.8B（6 層を置き換え、8+8 ヘッド、記憶 3,804 万パラメータ）

変換した時点で、生徒に注意のパラメータは 0。教師は同じ重みの上で動く。

### 段 1（層合わせ）：150 ステップ × 1,024 トークン＝153,600 トークン、33 分
設定：列 512×2、窓 128、スキップ 32（＋0〜96）、学習率 1e-3（余弦で減衰）。データは cosmopedia。

| 学習トークン | KL | PPL 比 | top-1 一致 | 層ごとの誤差（平均） |
|---|---|---|---|---|
| 0（記憶は初期値） | 1.308 | 3.62 | 0.504 | 1.173 |
| 51,200 | 0.767 | 2.11 | 0.639 | 0.614 |
| 102,400 | 0.735 | 2.06 | 0.659 | 0.527 |
| 153,600 | 0.737 | 2.05 | 0.658 | 0.509 |
| 参考：記憶を黙らせた場合（注意を取り除いただけ） | 1.210 | 3.33 | 0.526 | — |

- 層ごとの誤差は 6 層とも下がった（最後は 0.37〜0.67。層 15 が一番大きく、層 23 が一番小さい）
- KL は 5 万トークンまでで大きく下がり、その後は横ばい。段 1 は教師の入力の上で各層を合わせるので、層を通すうちに残りの誤差が積み重なる。ここを詰めるのが段 2
- 速さ：毎秒 約 80 トークン（CPU 2 コア）

### 段 2（全体蒸留）：40 ステップ × 384 トークン＝15,360 トークン、11 分
設定：記憶＋LoRA（階数 8、457 万パラメータ）、勾配チェックポイント、学習率 3e-4。メモリの都合で列 384×1。

| 学習トークン | KL | PPL 比 | top-1 一致 |
|---|---|---|---|
| 0（段 1 の終わり） | 0.507 | 1.63 | 0.731 |
| 7,680 | 0.464 | 1.53 | 0.708 |
| 15,360 | 0.399 | 1.47 | 0.722 |

- 1.5 万トークンで KL が 21% 下がった。全体を通した学習は効いている
- 評価は 3 列・1,149 位置だけなので、top-1 の上下は誤差の範囲
- 段 1 の表とは評価の列の長さが違う（384 と 512）ので、表どうしの数値は比べられない

### 評価（段 2 の後）
- 512 トークンの列：KL 0.502、PPL 比 1.68、top-1 0.690
- **想起：32 トークン前・400 トークン前とも、教師 4/4、生徒 0/4**。生徒は 8 件すべてに「123456」と答えた。文脈の数字を写す働きは、まだ学べていない
- 生成：文として自然で話題にも沿うが、中身は崩れる。例：
  - 「記憶は予測のためにある。」の英訳 → 教師 "Memory is for prediction."、生徒 "Memory is a memory of the past, not a prediction of the future."
  - 「日本で一番高い山」→ 生徒も富士山と答えるが、前置きが不自然
  - リストとタプルの違い → 生徒は "lists and lists" と書く

### 書き出し
- 注意を含まない単体のモデル（7.46 億パラメータ、bf16 で 1.49GB、1 ファイル）として保存し、元の Qwen の重み無しで読み直せた
- 保存ファイルの 380 個のテンソルに、注意の重み（q/k/v/o の射影、q/k の正規化）は 0。short の記憶 48、long の記憶 48
- 読み直した出力：第 1 候補はすべて一致。ロジットの最大差 0.12 は bf16 で保存した丸め（fp32 で保存する試験では一致）

## 4. この結果の読み方

- **確かめられたこと**：公式コードは本物のモデルの中で動き、学習でき、生成でき、注意なしで保存できる
- **確かめられていないこと**：
  - GPU での動作（公式の CUDA カーネル、コンパイルした FlexAttention、bf16）
  - 計画の学習量で、PPL 比 1.2 以下・想起の回復まで届くか。CPU の 17 万トークンでは PPL 比 1.5〜1.7、想起 0%
- 以前の線（元の注意を窓付きで残した構成）では、遠くの 1 つの事実の取り出しは約 1,000 万トークン（1,200 ステップ × 8,192 トークン）で 9 割前後に達した（Eureka-COM/memory-mosaics-LLM の docs/results/checks13.md）。今回は近くの読みも Mosaics の記憶が担うので、同じ量で足りるかは分からない。D1 の判定の基準に想起を入れてあるのはこのため
- 想起が戻らない場合の次の手：以前の線で効いた「複数の対応から正しいものを選ぶ」課題の列（Eureka-COM/memory-mosaics-LLM の `src/mmllm/synth.py`）を段 2 のデータに足す

## 5. 再現

```bash
python -m pytest tests/test_official_vendor.py tests/test_mosaic_qwen.py tests/test_mq_scripts.py
python scripts/mq_port27.py --out runs/port27
python scripts/mq_stage1.py --model Qwen/Qwen3.5-0.8B --data <cosmopedia のフォルダ> --docs 3000 --seq-len 512 --bsz 2 \
    --steps 150 --eval-every 50 --eval-rows 3 --short-heads 8 --long-heads 8 --window 128 --skip 32 --random-skip 96 \
    --skip-quantum 32 --warmup 15 --lr 1e-3 --out runs/cpu-s1
python scripts/mq_stage2.py --model Qwen/Qwen3.5-0.8B --data <同上> --docs 800 --delta-in runs/cpu-s1/delta --train mem+lora \
    --lora-r 8 --seq-len 384 --bsz 1 --positions 32 --steps 40 --eval-every 20 --eval-rows 3 --lr 3e-4 --warmup 3 \
    --lr-min-ratio 0.3 --skip-quantum 32 --grad-checkpoint --out runs/cpu-s2
python scripts/mq_eval.py --model Qwen/Qwen3.5-0.8B --delta runs/cpu-s2/delta --data <同上> --docs 800 --seq-len 512 \
    --eval-rows 2 --recall-distances 32,400 --recall-n 4 --max-new-tokens 24 --out runs/cpu-eval
python scripts/mq_export.py --model Qwen/Qwen3.5-0.8B --delta runs/cpu-s2/delta --out runs/cpu-export --weights-dir runs/cpu-export-weights
```
