## 1. 論文の中身（要点と行番号）

**記憶の単位（V1 150–166、198–204、225–230）**
- 記憶は列の始めに空で、位置ごとに（鍵, 値）を 1 組ずつ書き足す。鍵はそこまでの入力の要約、値は 1 つ先の入力を含む。読み出しは、今の鍵に近い過去の鍵の値の重み付き平均（ガウス核の回帰）
- 各ユニットは「近い未来の一片を予測する小さな機械」。値を作る重みが「何を予測するか」、鍵を作る重みが「どう予測するか」を決める。鍵と値の対応そのものは、推論時に列ごとに覚える（V1 233–240：学習はメタ学習）
- 値が 1 つ先を見るので、1 層で帰納ヘッド（…a b … a → b）ができる。位置の符号と、問いと鍵の区別は持たない

**注意との違い（V2 108–113、116–141／OW 449–457）**
- 鍵は長さ 1 に正規化し帯域 β を持つ。問いと鍵は同じ式（対称な核）。位置の符号なし
- 注意は鍵と値が同じトークンの射影なので、1 層では「その位置自身の表現」を取り出す。予測の対応を作るには 2 層以上が要る
- OW の言い方では、RoPE 付きの注意は「一貫しない」学習器（位置による減衰で実効的な記憶が限られ、文脈が伸びても帯域が狭まらない）。固定サイズの状態を持つ DeltaNet も、課題が状態より大きくなると一貫しない（OW 458–459、脚注 7：267–270）

**v2 の 3 つの変更（V2 148–238、290–295）**
- 帯域 β = β1·n^α + β0（覚えた組が増えるほど核を狭める）
- 鍵の漏れ平均を入力に応じた弁つきに
- 記憶を 3 層に：短期（直近 h = 256）、長期（直近 m 個を飛ばす。学習中 m は 64〜256 から引き、推論は 64）、持続（SwiGLU の MLP）
- m を乱数にするのは、位置に依らない信号を長期に、位置に依る信号を短期に割り当てさせるため。外挿が 15% 以上良くなる（付録の表 12）

**v2 の学習と結果（V2 275–281、313–340、380–404、940–942）**
- 最初から学習。small：24 層・幅 2048・16 ヘッド・2,000 億トークン。large：32 層・幅 4096・32 ヘッド・1 兆トークン。文脈 4,096 で学習し、32,768 で仕上げ
- 文書ごとのマスク（記憶は同じ文書の中だけを読む。理由は計算量：940–942）
- 普通のベンチマーク 19 個の平均は 52.2 対 52.2 で同等。個別には GSM8K が Transformer 32.4 に対し 27.4、MMLU は 49.0 対 48.2、HumanEval+ は 38.3 対 43.0（表 1：322–325）
- 長期記憶を外しても 13 個は変わらない（＝持続の記憶と短期で足りる課題）。SQuAD・BBH・math・MBPP・RACE の 6 個は大きく落ちる（付録の表 9）
- 複数文書の QA（RULER）：32k で 53.4 対 41.1。4k で学習しただけでも 8k・16k は保つ（48.8、46.4）、32k は 26.5 に落ちる（表 3・4：390–404）
- 例示からの学習（Banking77・TACRED・GoEmotions の分類）：10 ポイント以上の差。例示を増やすと v2 は伸び続け、Transformer は下がる（456–461）。ラベルを「class 1」のように無意味にした版でも同じ（486–520）

**OW：何が性質を生むか（OW 147–334）**
- 3 つの要件：推論時の学習、豊かな表現、予測による分離（入力と出力の表現を対応する小さな組に分け、組ごとに予測する）
- 仕組みの主張：内側の学習器が一貫していれば、長い学習長 l では学習器の誤差が消え、学習の圧力が表現に掛かって表現が豊かになる。短い l では、少ない例で当てる圧力が掛かり、表現が組に分かれる（220–227、296–299）
- 関連する課題のデータは溜めて使うべきだが、対象の課題と混ぜて 1 つの推定にすると、合わないものが害になり、溜まるほど悪くなる。別々に推定して混ぜる（312–323）

**OW：比べた構成（OW 420–518、付録 B：1084–1160）**
- (a) 基本：Memory Mosaics（文脈全体を読む長い記憶 1 本）、Transformer（RoPE）、DeltaNet
- (b) **今の混成**：DeltaNet か窓つき注意（2k）と、全域の注意（位置符号なし）を交互に並べたもの。最前線のモデルが向かっている構成として、**Qwen3.8 の設計の論文（Qiu ほか 2026）を引いている**（460–463、878–880）
- (c) ＋：長い記憶の**下に**短い記憶（窓 256 の注意。Mosaics でも DeltaNet でもよい）を置く。長い記憶は鍵の漏れ平均をやめて素の射影にし、直近 s 個を飛ばす（464–478）。短い記憶の実装は何でも同じ傾向（付録 G：1319–1326）
- (d) 二段：長い記憶を「今の文書」用と「前にある関連文書」用に分ける（494–515）
- 規模は 1.5B（24 層・幅 2048・16 ヘッド）と 8B（32 層・幅 4096・32 ヘッド）。ヘッドの次元 128（＝ヘッド数 × 128 がモデルの幅）
- 学習：1.5B は 4000 ステップ、8B は 8000 ステップ、1 ステップ 419 万トークン（＝168 億／335 億トークン）。同じ k-means の群（関連文書）から文書を引いて [bos]／[eos] で区切り、長さ l で切った列（371–377、1126–1160）

**OW：結果（OW 520–665、674–731）**
- Memory Mosaics は学習長 l を 4k → 64k に伸ばすほど良くなる。評価長 4k でも良くなる（表 1：48.55 → 49.19）
- 数学で微調整（MetaMath 26.2 万例）した GSM8K も、l（2k〜64k）とともに上がる傾向（図 3：551–558）。Transformer・DeltaNet・混成 2 種には系統的な伸びがない（図 4：622–636）
- **混成 DeltaNet は l を伸ばすと悪くなる**（表 2：評価長 4k で 48.57 → 46.24）
- ヘッド数（組の数）を増やすと Memory Mosaics は良くなり、Transformer と混成は悪くなる（表 3：GSM8K は 4 ヘッド 21.5 → 32 ヘッド 28.4）
- 著者は構成どうしの数値の優劣は比べないと明言している（細部で動くため。622–627）。パラメータ数を揃えた Memory Mosaics（43 ヘッド × 64 次元）は GSM8K 28.7〜30.8（付録 D）
- 一段のモデルは、関連文書を増やすと学習長のあたりで頭打ちか低下。二段の Memory Mosaics+ は伸び続ける。8B でも同じ形。「足りないのは容量ではなく構造」（721–731）

手元のデータで分かっていること：

- **Mosaics の層は、注意の層の働きをそのままは写せていない。** 段 1（各層で元の注意の出力を真似る）は 2,000 万トークンから横ばいで、誤差は平均 0.275、中ほどの層は 0.30〜0.40（docs/results/mq-27b-s1-2026-11-12.md）。段 2 のあとは平均 0.39。問いと鍵が同じで位置を持たないという作りの違い（V2 108–113）から予想されることで、計画 §7 にも弱点として書いてあった
- **長い記憶そのものは働く。** 学習長 2,048 の重みで、6,000 トークン前の番号を 10 問中 10 問（docs/results/mq-27b-recall-probe-2026-11-12.md）。位置に依らない読み出しが学習長の外で効いている（V2 の外挿と同じ向き）
- **数学が落ちた**（MMLU の数学 −26 ポイント、答案に計算の書き間違い）。論文の最初から学習した 8B でも GSM8K は Transformer より 5 ポイント低く（V2 表 1）、数学は強みとして主張されていない。ヘッド数が少ないと GSM8K が低い（OW 表 3）

## 3. 読んで分かったこと

1. **構成の形は論文から外れていない。** DeltaNet の層の上に Mosaics の記憶を置く形は、OW の「＋」（短い記憶は DeltaNet でもよい）に近い。使っているのは公式の v2 の層そのもの
2. **外れているのは学習のさせ方と測り方。** 論文の利点は「一貫した学習器を通して、長い列で表現を鍛える」ことから出る。今回は表現を凍結し、短い列で、性質を持たない側のモデルの真似をさせている。この目的では、真似が完全になっても得られるのは「配線を替えた Qwen3.8」で、Memory Mosaics の性質が出る理由がない
3. **真似そのものにも天井がある。** Mosaics の層は注意と別の部品で、同じ働きを 1 層では写せない。写せない分を周りの層の LoRA で埋める形になっていて、KL 0.165 と MMLU −7.2 はその残り
4. **27B で論文どおりの学習は、今の費用の枠では桁が合わない。** 論文は 1.5B でも 168 億トークン。今回の速さ（毎秒 約 1,100 トークン、3,000 万トークンで約 81 ユニット）では届かない
5. したがって決める必要があるのは目標：**(A) 元の 27B と同等のモデルを注意なしで作る**（今の道。Mosaics は部品として入るが強みは出ない）か、**(B) Memory Mosaics の性質が出るモデルを作る**（学習の目的・列の長さ・データの並べ方を論文に合わせる。まず小さい規模で符号が出るかを確かめる）か

## 4. 前回の説明（2026-11-13、要旨と README だけで書いたもの）への訂正

- 「層の種類を交互に並べるだけでは性質は得られない」と書いた点：原文では、その混成の例として Qwen3.8 型が名指しで引かれている。教師が「性質を持たない側」である、という重い意味がある
- 「論文は記憶を文書ごとに区切る」と書いた点：v2 の文書ごとのマスクの理由は計算量。関連のない課題を混ぜると害になる、という原理は OW §2.3.2 のほう
- 「注意の代役は苦手かもしれない（仮説）」と書いた点：段 1 の誤差の横ばい（0.275）という手元の証拠がすでにあった。仮説ではなく、作りの違いから来る既知の限界
- 「まず測る → 段 2 の続きを論文に寄せる」と進め方を書いた点：目標 (A)／(B) を決めるのが先。段 2 の続きは、どちらの目標かで中身が変わる
