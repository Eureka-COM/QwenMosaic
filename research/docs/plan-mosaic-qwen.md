## 1. 作るもの

```
元の層（Qwen の注意層）                 置き換え後（公式 MosaicBlock、Memory Mosaics v2 の構成）
  x += attention(norm(x))                 h  = attention_norm(x)
  x += mlp(norm(x))                       x += short(h) + long(h)          公式 MosaicsMemory × 2
                                          x += feed_forward(ffn_norm(x))   持続の記憶（SwiGLU）
```

- **short**：直近 256 トークンを読む Mosaics の記憶
- **long**：64 トークン以上前のすべてを読む Mosaics の記憶（学習中は 64〜256 の間でランダムにずらす）
- どちらも公式の仕組みのまま：鍵は過去の入力の漏れ平均（長さ 1 に正規化）、問いは鍵に帯域 `b1·n^a + b0` を掛けたもの、値は 1 つ先のトークンを見る、位置の符号は使わない
- 窓 256・スキップ 64・ランダム 192・ヘッドの次元 128・読み出しの弁あり・`flat` 配置は、公式の設定ファイル `configs/mosaics/memory_mosaics_v2.yaml` から読み込む（コードに数字を書き写していない）
- **持続の記憶と正規化**は、その層がもともと持っていた Qwen の MLP と RMSNorm の重みで始める。形が同じ（SwiGLU、RMSNorm）なので、Qwen が覚えた知識はそのまま残る
- **消えるもの**：各注意層の q/k/v/o の射影と q/k の正規化。27B では 1 層 1.05 億、16 層で 16.8 億パラメータ
- **増えるもの**：各層の short と long。27B（16+16 ヘッド）では 1 層 6,340 万、16 層で 10.1 億パラメータ
- 27B 全体：277.8 億 → 271.2 億パラメータ（実寸の層で数えた。`scripts/mq_port27.py`）

置き換えない 48 層（Gated DeltaNet＋MLP）は、注意ではなく固定サイズの状態を持つ再帰の層で、Qwen のまま残る。

## 2. 決めたことと理由

1. **替えるのは注意の全層（16 層）。Transformer 全体ではない**
   - 27B 級を Colab／Modal の費用で作るには、Qwen が何兆トークンもかけて覚えた重みを土台に残す必要がある。全 64 層を替えると、学習する量が約 4 倍になり、残る土台は MLP だけになる
   - 同じ 16 層を別の仕組み（Gated DeltaNet）に替えた公開モデルがあり、小さな学習量で元に近い値を出している（§4 の物差し）。16 層の置き換えは実現できる範囲にある
   - 全層を替える道は閉じていない。`--replace all` で 64 層すべてが MosaicBlock になり、生成まで動くことを試験している
2. **構成は Memory Mosaics v2（short＋long、どちらも Mosaics の記憶）**
   - 公式の構成のうち、注意を一切使わないのは「Memory Mosaics」（記憶 1 本）と「Memory Mosaics v2」（近く用と遠く用の 2 本）。最新の Mosaics+ は近くの読みに注意（窓付き）を使うので、「注意を残さない」に合わない
   - v2 は 10B・1 兆トークンまで大きくした実績がある構成（NeurIPS 2025）
3. **ヘッド数**
   - 0.8B：8+8（幅の比 1.0）と 4+4（比 0.5）を並べて学習する
   - 27B：まず 16+16（公式の設定ファイルと同じ数。幅の比 0.4。80GB の GPU 1 枚で段 1 が回る）。0.8B で 4+4 が 8+8 に明らかに劣れば、27B は 40+40（比 1.0、25 億パラメータ、H200 以上が必要）にする
4. **学習は 3 段。手本は元のモデル**（RADLADS の手順に倣う）
   - 段 1（層合わせ）：元のモデルを 1 回流し、各層で「元の注意の出力」を新しい記憶に真似させる。層ごとに独立なので、モデル全体の逆伝播が要らない。27B でも元のモデルの順方向 1 回分の計算で、16 層を同時に学習できる
   - 段 2（全体蒸留）：置き換えたモデルを自分の出力の上で動かし、次のトークンの確率分布を元のモデルに合わせる（KL）。学習するのは記憶と正規化、それに全層の LoRA（階数 32）。元の重みは凍結のまま教師と共有するので、27B でも重みは 1 組で済む
   - 段 3（長い列）：段 2 を 8k トークンの列で続ける
   - 教師と生徒は同じ重みを共有する。教師として動かすときは、置き換える前の層を使い、LoRA は切る
5. **データ**：英語の文章 4：対話 2：日本語 2：コード 1（cosmopedia／ultrachat／日本語 Wikipedia／codeparrot、いずれも公開・認証不要）。対話は Qwen の対話テンプレートで並べる
6. **保存**：小さいもの（ログ・数値・0.8B の重み）は従来どおり results ブランチ。27B の重み（約 2GB）は GitHub の Release に置く。ブランチに置くと保存のたびにリポジトリが 2GB ずつ増え続けるため（リポジトリはすでに 5.6GB）

## 3. 公式コードの扱い

- `third_party/MemoryMosaics/`：公式リポジトリ（commit c2ca0e8、2026-10-23）の `model/`・`configs/`・`inference/` を無改変で置いた。`UPSTREAM.json` に全 49 ファイルの SHA-256 があり、変換のたびに照合する。1 文字でも変えると変換が止まる
- 置き換えた層で動くクラス（`MosaicBlock`、`MosaicsMemory`、`LeakyAverage`、マスク、位置）は、すべてそこから読み込んだ公式のもの
- 公式コードには、動く場所が限られる部品が 2 つある。ファイルは変えず、呼び出しの手前で切り替える（`src/mmllm/official.py`）：
  - **FlexAttention**（記憶の読み出し）：PyTorch に CPU での逆伝播が無い。GPU の学習では公式の呼び出しをそのまま使い、CPU と、GPU での評価・生成（勾配なし）では、同じ計算を密な行列で行う。両者が一致することを試験している
  - **漏れ平均の CUDA カーネル**：nvcc が無いと作れない。作れる環境では公式カーネルを使い、作れなければ同じ漸化式を並列に計算する版に切り替える（公式の参照実装と一致することを試験している）
- どちらの経路で動いたかは、毎回 `run.json` と `env.json` に記録する

## 4. 測るものと判定の基準（GPU の結果を見る前に決めた）

毎回、元のモデル（教師）と置き換えたモデル（生徒）を、学習に使っていない文書で比べる。

| 指標 | 意味 |
|---|---|
| KL | 次のトークンの分布の、教師からのずれ（0 が一致） |
| PPL 比 | 生徒の perplexity ÷ 教師の perplexity（1.0 が同じ） |
| top-1 | 次のトークンの第 1 候補が一致する割合 |
| 層ごとの誤差 | 教師の入力を与えたとき、記憶の出力が元の注意の出力からどれだけ外れるか（相対二乗誤差） |
| 想起 | 「◯◯の暗証番号は 12345」を 32／512／1,500／6,000 トークン前に置き、質問して 5 桁を答えさせる。256 より遠い距離は long の記憶でしか運べない。生徒の正答率 ÷ 教師の正答率 |
| 生成 | 5 つの問い（日本語 2、コード 1 を含む）への答えを並べて読む |

**物差し**：Qwen3.8-27B の同じ 16 層を Gated DeltaNet に替えた公開モデル（summerAIO/Qwen3.8-27B-Longbook27-v2）は、KL 0.207・PPL 比 1.148 と記録している（同モデルの `gdn24_metadata.json`、2.9 万トークンで測定）。

**D1（0.8B で全手順）の判定**

| 判定 | 条件（段 2 または段 3 の終わり、8+8 ヘッド） | 次にすること |
|---|---|---|
| 合格 | PPL 比 ≤ 1.20、かつ KL ≤ 0.20、かつ想起（生徒÷教師）が 1,500 で ≥ 0.8、6,000 で ≥ 0.6 | 27B の試走（P27）→ 27B の段 1 |
| 保留 | 合格に届かないが PPL 比 ≤ 1.5 で、最後の 3 回の評価で KL がまだ下がっている | 0.8B のまま学習量を 2〜3 倍にして、もう一度判定する |
| 中止 | 段 2 の後も PPL 比 > 1.5、または 1,500 の想起が教師の 0.3 未満、または段 1 で層ごとの誤差が 0.5 を切らない | 27B に進まない。層ごとの誤差と想起から原因を調べ、構成（ヘッド数、記憶 1 本の構成）を見直す |

- 動作の条件（どの判定でも必須）：教師＝元のモデルの差が 0、書き出したモデルに注意のパラメータが 0、書き出して読み直した出力が一致
- 記憶の大きさ：4+4 の PPL 比が 8+8 より 0.03 以上悪ければ、27B は 40+40 にする。それ以内なら 16+16

**27B の判定**：段 3 の終わりに PPL 比 ≤ 1.15・KL ≤ 0.21（物差しと同じ水準）で合格。その後、一般のベンチマーク（MMLU・GSM8K など、既存の評価スクリプト）で元の 27B と比べる。

## 5. 費用と損益の分かれ目

料金：Modal は 1 時間あたり A100-80GB $2.50、H100 $3.95、H200 $4.54、B200 $6.25。Colab の A100 は 1 時間 約 9 ユニット（probe27 の実績）。

**0.8B（D1）**：1,000 万＋1,000 万＋400 万トークン、2 つの大きさを並列。
- 見込み：A100 で 1.3〜1.5 時間（約 12〜14 ユニット）、H100 なら約 50 分（約 $3.5）
- 根拠：0.8B の蒸留の実測（A100 で毎秒 約 9,900、H100 で 約 18,200 トークン。逆伝播あり）。段 1 は逆伝播が無いのでこれより速いはず。新しいコードでは未測定で、最初の `env` の実行が実測に置き換える

**27B**：どれも probe27 の 1 回の実測（A100、10,240 トークンの順方向＋逆方向で 13.5 秒）からの推定。P27（約 $2、または約 5 ユニット）が実測に置き換える。

| 学習量（段 1／段 2／段 3） | 段 1 | 段 2 | 段 3 | 合計の目安 |
|---|---|---|---|---|
| 最小：1,500 万／1,500 万／400 万 | 約 $4 | 約 $17 | 約 $5 | **約 $26** |
| 標準：3,000 万／3,000 万／800 万 | 約 $7 | 約 $33 | 約 $10 | **約 $50** |

- 速さの仮定：段 1 は H100 で毎秒 約 5,000 トークン（順方向 1 回）、段 2・段 3 は毎秒 約 1,000 トークン（教師＋生徒＋逆伝播＋再計算）
- 80GB に載るか：段 1 は載る見込み（重み 50GB＋記憶と最適化の状態 約 12GB）。段 2 は LoRA と勾配チェックポイントを入れて 1 列ずつなら載る見込みだが、余裕が小さい。載らなければ H200（141GB）を使う（1 時間 $0.59 高いだけ）。P27 で実測する
- Modal の毎月 $30 の枠なら、「最小」は 1 か月に収まる。「標準」は 2 か月か、段 1 を Colab（約 28 ユニット）に回す

**損益の分かれ目**
- D1 が中止なら、27B には 1 円も使わない
- P27 で段 2 が H200 にも載らない、または速さが仮定の半分以下なら、27B の学習量と GPU を決め直す
- 27B の段 1 は 500 万トークンごとに評価を残す。1,000 万トークンの時点で層ごとの誤差の平均が 0.6 を切っていなければ止める（0.8B の同じ時点の値と比べる）
- 27B の段 2 は、最初の 300 万トークンで KL が下がらなければ止める

## 7. 分かっている弱点と、まだ確かめていないこと

- **CPU で確かめた範囲**（docs/results/mq-cpu-2026-11-12.md）：本物の 0.8B で、段 1 は層ごとの誤差を 1.17 → 0.51、段 2 は KL を 0.51 → 0.40 に下げた。向きは正しいが、学習量は計画の 0.7%（約 17 万トークン）で、PPL 比は 1.5〜1.7、**想起は 0%**（教師は 100%）。計画の学習量で想起が戻るかが、D1 で確かめる中心

- **GPU では 1 度も動かしていない**。公式の CUDA カーネルの組み立てと、コンパイルした FlexAttention の動作は、最初の `env` の実行で初めて確かめる。動かなくても代わりの経路で学習は進む（遅く、メモリを多く使う）
- **Modal の新しいイメージ**（CUDA 開発環境つき）と **GitHub Release への保存**は、こちらの環境から試せなかった。P27 と D1 の書き出しで初めて動く
- **問いと鍵が同じ**という Mosaics の仕組みは、問いと鍵を別々に持つ注意の働きを 1 層で完全には写せない。段 1 で誤差が残る分は、段 2 で周りの層（LoRA）が合わせる前提。合わせきれるかは D1 で分かる
- **置き換えない 48 層は Gated DeltaNet のまま**。Memory Mosaics の論文は、この種の固定サイズの層を混ぜた構成では「例を増やすほど良くなる」性質が弱まると報告している。今回の目的（27B 級のモデルを作る）には影響しないが、その性質を狙うなら `--replace all` の道になる
- **キャッシュの大きさ**：long の記憶は 1 トークンあたり 4,096 個の数（元の注意は 2,048 個）。short は直近 256 トークン分だけで足りるが、公式の実装は全長を確保する
- **バッチ内の詰め物**：記憶は詰め物のトークンを避けない。長さの違う入力をまとめて生成するときは 1 件ずつ流す
- **以前の評価スクリプト**（多数例の曲線、RULER 型、MMLU、GSM8K）は Eureka-COM/memory-mosaics-LLM にあり、旧い組み込み用の入口を使っている。新しいモデルで回すには、入口を付け替えてこちらへ移す必要がある（27B の判定までに行う）
- 過去の結果（checks12〜24、Eureka-COM/memory-mosaics-LLM）は、元の注意を窓付きで残した別の構成のもので、この構成の結果としては使わない

## 8. 追記（2026-11-12）：27B の想起の切り分け（学習なし）

**なぜ**：27B の最後の評価で、6,000 トークン前の想起が 0/20 だった。問いを作り直して調べると、間違いはすべて「質問の前に会話の文書がある問い」で、6,000 の問いには会話を含まないものが 1 つも無かった（docs/results/mq-27b-recall-review-2026-11-12.md）。長い記憶が遠くまで届くのかどうかが、今の評価では分からない。

**前提との照合**：前提 1〜3 に関わる変更は無い（構成・公式コード・学習の場所は同じ）。評価の足し方は前提 4 で任された範囲。§4 の判定の基準は変えない。この測定は原因を分けるためのもので、合否は付けない。

**測るもの**（`scripts/mq_recall_probe.py`、計画 `mq-27b-recall-probe.json`）：元の 27B（教師）と、段 1・段 2・段 3 の重み。答えを後ろに付けて 1 回流し、答えの位置の確率を読む（生成は使わない）。

| 問いの作り方 | 距離 | 分かること |
|---|---|---|
| 評価と同じ（詰め物に会話が入る）80 問 | 32／512／1,500／6,000 | 「発言の終わり」を選ぶ確率と、数字を取り出す確率を分けて見る |
| 会話を含まない詰め物 | 32／512／1,500／3,000／6,000、各 10 問 | 長い記憶そのものが遠くまで届くか |
| 会話の形（ユーザーの発言に文書と質問、アシスタントが答える） | 512／1,500／6,000、各 8 問 | 実際の使い方で想起できるか |
